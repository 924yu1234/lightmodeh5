# 国际化规范

## 基本规则

```tsx
const intl = useIntl();

// ✅ 正确
{intl.amount}
{intl.turboRange.min_price}
{intl.min_XXX.replace('XXX', '0.01')}

// ❌ 禁止
{'Amount'}                        // 硬编码
{intl.amount || 'Amount'}         // fallback 模式
{intl.amount ?? 'Amount'}         // fallback 模式
```

## 文件结构

```
src/locals/
├── en.tsx          # 英文（源头，所有 key 以此为准）
├── zh-CN.tsx       # 简体中文
├── zh-TW.tsx / ja-JP.tsx / kr.tsx / fr.tsx / es.tsx
├── de.tsx / it.tsx / ru.tsx / uk-UA.tsx / tr.tsx / vi.tsx
├── index.tsx       # barrel 入口
├── intlUtils.tsx   # 工具（toCsv 等）
└── map.tsx         # 语言映射
```

## 嵌套对象

```tsx
const en = {
  amount: 'Amount',
  turboRange: {
    min_price: 'Min Price',
    investModeSingle: 'Single',
    investModeDual: 'Dual',
  },
  meme: { ... },
  stocks: { ... },
};
```

## 使用原则

- 子组件内部直接 `useIntl()`，不要父组件翻译后当 props 传
- 不在多层组件间传递 `intl.xxx` 或翻译 key
- 表格列标题、按钮文案、状态文案就近在所属组件内处理
- 含单引号的翻译用双引号包裹：`"Augmenter l'investissement"`
- 不允许写 `intl.xxx || 'text'` / `intl.xxx ?? 'text'` 这类 fallback
- 文案只能从需求文档获取并添加到 `src/locals/*`，不要根据实现需要自行编写文案
- 如果需求文档里没有对应文案，必须先和需求方 / 提需求的人确认后再补，不允许主观新增
- 不要在组件里兜底字符串，也不要为了补齐交互先临时造一版文案
- 新增 intl 文案只能从需求文档获取，禁止自己生成、润色、补同义文案
- 需求文档未提供的文案必须先确认，再决定是否新增 key
- 需求文档中已有翻译表时，必须按原文录入 `src/locals/*`，不允许擅自改写

## trade-fe vs wallet 国际化边界

- **trade-fe**：添加需求文档中的所有文案（即使当前未使用）
- 需求文档最下方如果有“翻译内容 / 中英文文案 / 文案对照表”这类区域，里面的中英文内容必须完整补到 `trade-fe` 的 `src/locals/*`
- 只要需求文档中已经给了翻译表，就以文档原文为准；不得自行改写、润色、缩写或补充同义句
- 不允许因为“当前页面没接上”或“暂时未使用”而省略需求文档底部的翻译文案
- 英文以 `src/locals/en.tsx` 为源头，同时补齐 `zh-CN.tsx` 对应内容
- **wallet**：只添加确认弹窗中实际使用的文案
